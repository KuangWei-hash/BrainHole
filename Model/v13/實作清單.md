# v13 實作清單

2026-11-22，以下均為待辦規格，並非已存在的可呼叫 API。本次只建立設計文件，不啟動實作或訓練。

## 1. 實作順序與邊界

1. 建 `v13/base.py`：包裝固定 v12、依 phase scatter 出 M/A/V、明確窗口方向與重置狀態。保持 target-free，先做逐值重現。
2. 建 `v13/data.py`：由 schema v4 枚舉完整窗口、保存 split keys manifest，訓練標籤讀取與 inference_inputs 分離。可借用 v11 邏輯，先處理 UNC SQLite 的已知問題，不直接假設舊入口可用。
3. 建 `v13/model.py`：R0/R1 同尺寸殘差 CNN、可還原 config、零初始化與 alpha bypass、量化政策。
4. 建 `train_v13.py`：run_logged、每輪 update_active_record、完整開發集、固定預算、checkpoint 節點／選模及失敗留存。
5. 建 `predict_v13.py`：載入一組 checkpoint、讀16幀本條、輸出 RAW8／PNG及完整來源資訊；不允許 target 查詢。
6. 建 `evaluate_v13.py`：相同 keys 同時計算 v12 與 v13，RAW／RGB／頻帶／時序／條界分列，各方法各自成片。
7. 建 `test_v13.py` 與必要既有回歸整合。通過 S0 後執行 S0-fit，再依條件啟動 S1；任何訓練都須遵守[研究預算](實驗與驗收計畫.md)。

輸出路徑建議 `Model/runs/v13-<stage>-<variant>-<timestamp>`，每次新目錄，不覆寫舊結果。程式碼放 Model 既有入口位置以便記錄快照；需確認記錄器遞迴收錄 `v13/`，必要時擴充，不能以「已有 run_logged」取代查核實際快照。

## 2. 預定 CLI 契約

尚未實作，先列必要語意，不提供可直接執行的命令：

| 入口 | 必要參數／行為 |
| --- | --- |
| train | db、scene-plan、split-manifest、out、variant、device、seed、epochs、batch-size、microbatch、lr；固定 v12 版本／history16／decay2；拒絕不相容快取 |
| predict | db或因果decoded串流、checkpoint、frame、block、out、alpha；回傳是否暖機／回退；不讀標籤 |
| evaluate | db、scene-plan、split-manifest、checkpoint、out、alpha、video；固定相同窗口重跑 v12；各方法獨立影片 |

訓練需原子寫入 config／metrics／checkpoint，檢查有限數，異常退出由記錄器標為 failed。若實作 resume，保存 model、optimizer、RNG、sampler／進度及完整 config，恢復時核對資料／底圖指紋；沒有完整狀態不能稱無縫續訓。

## 3. 必要正確性測試

這些測試針對可能導致假成果的契約，不只是重述模型層數：

- 16相位 scatter 和 pack/unpack 往返：四個 CFA byte 不交換，輸出位置與來源對應，age0/15與 DB phase 轉換正確。
- 相同 decoded 下 v13 底圖與現有 v12 **byte-for-byte** 相同，涵蓋邊界、等距、排除owner及不同phase起點；不把浮點重寫當等價。
- 正常完整窗口覆蓋率、owner年齡、暖機／缺幀／cut／header變更／split重置；舊內容不得穿過重置點。
- 零初始化結果等於 v12；alpha0直接回傳底圖byte；載入權重前後一致；輸入順序翻轉須被檢查或產生明確不同的已知測例。
- 封鎖／移除 target 欄位後 inference_inputs 仍可執行；改 target 不改 B/M/A/V及推論；不因評估器先讀 target 而混淆推論無洩漏證明。
- manifest 交集與每個樣本歷史範圍檢查：train/dev/audit的來源窗口不跨界，scene manifest SHA匹配，所有 missing keys顯式報告。
- batch16與microbatch4更新在可控小樣本下相容，最後不足batch時loss權重正確；關閉隨機層後batch組成不改推論。
- RAW輸出尺寸／長度10,240 bytes、有限值、量化政策、clipping統計；影片整段解碼、fps／尺寸／幀數、暖機標記。
- 記錄器在成功與人工觸發失敗兩種情況都留紀錄，含v13程式快照／原argv／資料和權重指紋；不能只測完成路徑。

不為這次純文件變更新增可執行測試；上述項目隨對應實作加入，流程檢查也要留紀錄。

## 4. 每組最小交付物

| 位置 | 內容 |
| --- | --- |
| experiments/records | config、manifest指紋、每輪曲線、狀態、起訖、環境、argv、底圖／程式快照、失敗原因 |
| experiments/details | 每frame/block的方法分數與分組，避免僅存總平均 |
| runs/<唯一目錄> | 權重、原始RAW／必要PNG、各方法單獨MP4、FFmpeg紀錄、report |
| Model/實驗紀錄-v13-*.md | 目的、唯一變因、窗口／樣本數／預算、選模、數值、目視結果、限制、產物連結 |

report須能回答：本片是哪個checkpoint與輪次、多少幀實際由AI修復、哪些是暖機、底圖是哪一版、alpha多少、相同keys的v12分數多少。交付影片不能只寫「best」而不標選模依據。
