# v13 實驗與驗收計畫

2026-11-22，預先登錄的研究計畫，尚無 v13 實驗結果。先確認品質可行性，再量測即時性；使用者將現有 v12 定為人眼最低合格線。

## 1. 資料與切分

BBB Q5 schema v4，沿用資料庫與場景清單的指紋，見[設計規格](設計規格.md)。每幀 30 條，同條完整歷史 16 幀。下表範圍皆為 **包含上限**；CLI 不論採何種範圍形式都要在 config 明列。

| 階段／用途 | 允許讀取的來源幀 | 實際目標幀 | 預期目標條數 |
| --- | --- | --- | ---: |
| S1 場景訓練 | 691–719 | 706–719 | 420 |
| S1 開發驗證 | 721–750 | 736–750 | 450 |
| S2 訓練 | 0–719 | 每個場景／切分起點後第 15 幀起 | 19,800 |
| S2 開發驗證 | 721–779 | 736–779 | 1,320 |
| S2 保留審核 | 780–899 | 795–899 | 3,150 |

S2 訓練按起點 0、356、472、691 重置，720 個來源幀扣除 4×15 個暖機幀，為 660×30=19,800。所有條數為依現有連續資料與切場資訊推算；實作以 keys manifest 核對，資料缺失時不能硬湊。

開發驗證、保留審核各自暖機，不跨分區讀歷史。第 720 幀保留空隙，不作偷接歷史用途。S1 開發已包含在 S2 開發，不稱為新驗證。舊 v10/v12 已看過 BBB 的後段，本次「保留審核」只是禁止 v13 調參回看的研究約束，**不是真正從未看過的盲測**。不能宣稱跨片泛化；真正最終測試需另留新影片／未參與開發的場景。

為重現 v12 既有 736–899 全區間，可額外做同窗口的歷史對照表，但不能把該表混稱為本計畫的獨立審核分數。S2 審核必須重跑 v12 在同一 780 起點的歷史重置條件。

資料增強首版關閉。隨意翻轉 RAW 會改變 CFA 與 phase，不能直接套 RGB augmentation。快取以 uint8 保存 B/M/A/V 或可還原的最小量，保存 DB、場景、程式與窗口指紋；不同 split 不共用有狀態的歷史隊列。

## 2. 逐階段預算與停止點

| 階段 | 工作 | 上限／通過條件 |
| --- | --- | --- |
| S0 | 底圖重現、無標籤推論、窗口與 alpha=0 檢查 | 無正式訓練；任何錯位先修，不帶病跑大實驗 |
| S0-fit | 32 條固定訓練樣本的過擬合診斷 | 最多 200 optimizer updates；無法明顯擬合先查實作，不宣稱品質 |
| S1-R0 | 僅 B 的殘差 CNN，RAW L1 | 40 輪，420 條／輪；batch16、drop_last=False，27 updates／輪，共 1,080 |
| S1-R1 | B＋M＋A＋V，同一網路與損失 | 同 R0 的樣本、seed、輪數、更新數 |
| S1-R2 | 在 R1 上加入梯度項 | 條件式第三組；同預算，只改損失 |
| S2 | 小場景通過後，把選定方案從頭訓練 | 最多 2 組、各 20 輪；每輪 19,800 條，1,238 updates／輪，共 24,760／組 |
| S3 | 新場景／新影片及串流效能 | 前面只代表同片可行性；範圍與新資料需另登錄 |

統一初始設定：seed42、FP32、AdamW（lr=1e−4、betas=(0.9,0.999)、weight_decay=0）、有效 batch16、microbatch4、固定學習率、gradient clip norm1。每個 optimizer step 將各 microbatch 的 loss 按實際樣本數加權，最後不足 16 條不以錯誤分母縮小梯度。相同 seed 保持相同 key 順序，通道維度不同造成的初始化差異如實記錄。

這些是首輪控制變因用的配置，不是已驗證最優超參數；不依單次驗證結果無上限地掃參。S1 最多三組，若都只更平滑或增加條紋，停止現有後修復設計並寫負面結果。S2 第二組優先用選定方案的 seed43 重複驗證；若要改架構，先另寫變因，不能同時換資料、loss 和容量。

## 3. 選模與保留審核

每輪在完整開發集記錄 v12／v13 的同 keys RAW8 MAE、PSNR、RGB 指標、按 phase／age／block 分組及裁切比例；S1 只有 450 條，S2 只有 1,320 條，不再用 128 條子集假裝完整驗證。

每組保存 `last.pt`、`best-mae.pt` 和預登錄節點。S1 節點為第 10／20／40 輪，S2 為第 5／10／20 輪。目視候選限定 best-mae 與這些節點，避免事後掃所有輪次挑最好看的短片。最佳 MAE 輪與最終視覺候選分開命名，候選所依的窗口／理由寫入紀錄。

在開發集選定架構、輪次、alpha 和量化方式後，凍結 config／權重雜湊，再執行 S2 保留審核。若看完審核再改模型，該區間轉為開發資料，後續不得繼續稱為保留測試。

alpha 主值 1，0 為一致性基準，0.5 為預登錄診斷；如開發集選 alpha0.5 作交付，審核前固定。不得依個別影格的標籤挑強度。

## 4. 對照與指標

必要對照：原樣 v12、v12＋固定同色平面 unsharp（alpha0.5、Gaussian5 sigma1，若未有函式需先明確實作）、R0、R1；R2 如有執行則列出。v10 的第 40 輪只作相同重疊窗口的歷史參考，註明兩幀／16 幀輸入差異。必要時增加 v12＋等能量高通噪聲診斷，能量僅以訓練集校準，不從驗證標籤挑選。

| 類別 | 量測與解讀 |
| --- | --- |
| 內容失真 | RAW8／RGB MAE、PSNR、逐條勝率、最差退步 keys；RGB 參考是 target RAW 顯色，不是原片 RGB |
| 細節 | 同色 CFA 高低頻誤差、邊緣梯度誤差、固定 ROI 目視；高頻能量增加不算改善 |
| 時序 | 同一有效 frame pair 的 `mean(abs((P_t−Y_t)−(P_prev−Y_prev)))`，與 v12 同 pairs 比較；固定座標、無運動補償，不是純閃爍分數 |
| 條界 | 完整 RAW 拼回後，在同色 CFA 平面比較邊界與條內的預測誤差差分；記錄 rows/cols 與歸一化，不能把 RAW 相鄰異色 byte 差當條縫 |
| 異常 | 越界、裁切、非有限數、delta 大小、缺失／fallback keys、暖機與切場後表現 |
| 可部署性 | 後續量測 decoded→v12→AI→RAW8 的 batch1 延遲、P50/P95/P99、每秒900條吞吐和排隊；解碼、顯色、影片編碼另列 |

完整畫面允許評估器用多條輸出拼圖及量條界，但每條的模型輸入仍獨立。若以成片與原始來源 RGB 比較，另報來源 frame mapping、24→30 fps 重複幀、縮放、顯色及 H.264 影響，不和 RAW 顯色參考混為一談。

## 5. 人眼合格線與影片交付

先固定 v12 的 ROI 和同一組驗證幀，再看模型，不事後只挑改善位置。S1 建議幀 736、743、750；S2 開發幀 736、750、779；審核幀 795、844、874、899。ROI 座標須在 S0 建 manifest 並凍結，先查看 target/v12 決定草地、樹根／洞口、葉片、標題邊緣及條界位置，實際可見區域如實記錄。

人眼對每個 ROI／片段標記較好、相當、較差，並說明是哪一項：

1. 草地／枝葉結構是否仍清楚，有無變成光滑色塊或無方向細斑。
2. 輪廓、洞口、物體位置與主要色彩有無變形、溢色或重影。
3. 條紋、顆粒與接縫是否減少，是否以抹除真細節換取乾淨。
4. 播放時有無新增閃爍、紋理爬動、殘影及切場污染。

**超過 v12 的判定**：預登錄 ROI 至少一類缺陷有清楚且可重現的改善，其餘重要結構不退步，連續影片不新增明顯時序缺陷。只有「差不多」表示守住底線，尚未證明 AI 有價值；MAE 更低但模糊則失敗。視覺變好但失真增加者列為有取捨候選，揭露數值與失敗位置，不自動宣告全面通過。

每個方法／checkpoint／alpha **各自輸出**原解析度 640×480、30 fps 影片，不產生並排 `comparison.mp4`。S1 成片來源 721–750 共30幀、其中前15幀暖機；S2 開發721–779共59幀、審核780–899共120幀，各自前15幀暖機。另交付有效窗口版供只看 AI 成果，檔名和 report 清楚標明，不能隱藏暖機缺陷。

將 v12 與 v13 用相同 CFA 顯色、量化、FFmpeg 設定輸出，整段解碼並核對幀數／fps／解析度。以獨立影片在相同縮放與播放速度切換觀看；靜態 PNG 只能支持畫面判讀，不能證明時序穩定。

## 6. 實驗紀錄與資源

所有訓練、流程檢查、失敗、推論、快取建立和效能量測接入 `run_logged`；每輪 `update_active_record`。config、窗口清單與小型結果存 `experiments/records`，逐條值存 `experiments/details`，權重／PNG／MP4 存唯一新 `runs/` 目錄，補寫 Markdown 並更新實驗總表。

GPU／Python 環境目前 **未對 v13 驗證**。v10 環境文件中的本機 probe 路徑已在本次工作中觀測到缺失，不直接照抄為可用環境。執行前重新確認實際 Python、torch、CUDA、GPU、磁碟、FFmpeg。SQLite／CLI 若遇 SMB 問題，用本機資料副本核對雜湊；工作與產物根目錄仍是 W:\BrainHole。不得因跑不起來就跳過紀錄或改用標籤生成輸入。
