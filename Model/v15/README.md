# v15：v12 與 v14 各自獨立計算後的 50/50 融合

2026-11-23，使用者肉眼比對 v12 與 v14（compact codebook＋相位保護＋30/70 遞迴混合）後指出：**v12 的缺點是快速移動物體因時間混合延遲而扭曲，優點是靜止時紋路最清晰；v14 的優點是外型完整不扭曲，缺點是紋路明顯不如 v12**（即使 v14 的 RAW MAE 較低）。v13 的既有設計文件也記錄過同一種「分數與觀感不一致」的現象（v10 對 v12）。

v15 的做法最單純：v12、v14 各自完全獨立計算完整的 640×16 輸出，再把兩張成品畫面逐 pixel 做 50/50 平均（[v15/__init__.py](__init__.py) 的 `blend()`），不做任何相位保護或門檻判斷。入口見 [export_v15_v12_v14_blend.py](../export_v15_v12_v14_blend.py)。

## 結果

在與先前相同的 90 幀評分窗（frame 1763–1852）：

| 方法 | RAW MAE |
| --- | ---: |
| v12 | 7.5194 |
| v14（compact+30/70混合） | **5.5386（數值最佳）** |
| v15（v12+v14 各半） | 5.9858 |

v15 的 MAE 介於兩者之間、比 v14 單獨差——這是單純平均「一個較準＋一個較不準」的預期結果，除非兩者誤差型態互補，否則數值上不會超越較準的那個。

**但使用者目視後確認：v15 是肉眼看起來最舒服的版本**，即使分數沒有超越 v14。這與專案 `驗收標準.md` 一貫立場一致：數值初篩通過（或較佳）不代表視覺驗收通過（或較佳），反之亦然——視覺判讀優先。**目前 v15 是示範片段上使用者實際採用的候選**，跨片泛化、即時效能、以及是否該替換成更精細的加權（而非死板 50/50）都還沒驗證。
