# 解碼放大基準與第一輪改良

本文件只記錄舊 v1／v2 純 bytes 輸入的實驗。後續正式規格已改為雙輸入，結果見 [v3 雙輸入實驗紀錄](./實驗紀錄-v3雙輸入.md)；本文件「未達標」結論不涵蓋新 v3。

## 結論

依 [驗收標準](./驗收標準.md)，**本次所有模型仍未達標**。
最佳單幀模型微調後 RAW MAE 由 31.04 降到 30.09，但仍不及解碼後雙線性放大的 28.76，PSNR 也較低。
第二版低解析度輔助監督沒有帶來改善，保留作實驗候選，不取代最佳模型。

## 相同資料與公平基準

- 資料：Q=6 schema v3，900 幀、27,000 區塊；前 720 幀訓練、後 180 幀驗證。
- 所有表列方法使用完全相同的 5,400 個驗證區塊；沒有只挑較有利的部分資料。
- 解碼：從共用標頭與 payload 重建完整碼流，使用現有 OxideAV bridge 解碼，沒有從高解析度標籤產生輸入。
- 共解碼 23,231 種不同碼流，對應全部 27,000 筆。開頭、中間、結尾共三筆與舊版單筆解碼 CLI 逐 byte 一致。
- 放大：拆開四個 RGGB 平面，依 phase 座標進行 nearest／bilinear 插值，邊界採 border 延伸，再交錯回 RAW。
- 顯色：完整 30 區塊拼成一幀後，各方法採相同的固定 bilinear Bayer 顯色，不加入獨立調色。
- 所有模型推理只讀 bytes、phase、長度，不讀取解碼快取。快取僅用於 v2 輔助訓練標籤及驗收對照。

這仍是同一部影片的前後切分，並用驗證集選最佳權重，不能當作獨立新影片測試。

## 結果

| 方法 | RAW MAE ↓ | RAW PSNR ↑ | 區塊 MAE 同時勝過兩基準的比例 | 數值初篩 |
| --- | ---: | ---: | ---: | --- |
| 解碼 + nearest | 30.42 | 16.00 dB | — | 對照 |
| 解碼 + bilinear | **28.76** | **16.68 dB** | — | 對照 |
| v1，原始 3 輪 | 31.04 | 14.72 dB | 54.26% | 未通過 |
| v1，較低學習率再微調 3 輪 | **30.09** | 14.79 dB | 59.43% | 未通過 |
| v2，輔助監督 8 輪中最佳 | 33.00 | 14.45 dB | 49.50% | 未通過 |
| v2，調整後再訓練 4 輪中最佳 | 32.20 | 14.66 dB | 52.63% | 未通過 |

區塊勝率超過一半不代表整體通過：部分區塊的大幅退化仍使平均誤差與 PSNR 較差。
這些實驗的訓練輪次、起始權重與 loss 不同，不宜把差異全歸因於架構本身。

## 本次改動與可重現設定

1. 新增 `baseline.py`：重建碼流、批次解碼、儲存含資料庫及解碼器 SHA-256 的離線快取。
2. 新增 `evaluate.py`：同樣本對照、逐區塊紀錄、數值初篩、完整幀 RGB 與對照總圖。
3. 新增可選 v2：bytes → 預測低解析度 RAW → phase 對齊放大 → 小型 CNN 殘差修正，約 166 萬參數。
4. 新增 `--warm-start`：只載入權重、optimizer 重新建立，要求相同架構、歷史、標頭、來源與切分，記錄起始 checkpoint。

v2 初始設定為低解析度輔助 L1 權重 1、殘差幅度 0.1、Adam lr=0.001，完整 8 輪。
調整版從其最佳權重開始，以輔助權重 0.1、殘差幅度 0.5、lr=0.0003 再訓練 4 輪。
v1 微調從原始最佳權重開始，lr=0.0003，完整再訓練 3 輪。全部 batch size 8、seed 42。

```powershell
# 延用 Model/README.md 的 $datasetPath
.\Model\.venv\Scripts\python.exe Model/train.py --db $datasetPath --architecture v1 --history 1 --device cuda --epochs 3 --lr 0.0003 --warm-start Model/runs/single-v1/best.pt --out Model/runs/single-v1-refined
.\Model\.venv\Scripts\python.exe Model/train.py --db $datasetPath --architecture v2 --decoded-cache Model/runs/decoded-q6.npz --history 1 --device cuda --epochs 4 --lr 0.0003 --auxiliary-weight 0.1 --residual-scale 0.5 --warm-start Model/runs/single-v2/best.pt --out Model/runs/single-v2-tuned
```

若重跑須另選輸出目錄，程式拒絕覆寫既有實驗。

## 目前瓶頸與後續方向

v2 預測的低解析度 RAW 與真正解碼結果之間，驗證 MAE 仍為 36.43；調整版為 37.93。
因此加入解碼監督並沒有讓目前前端穩定重現輸入已有的內容。這支持先處理 bytes 前端與資料泛化問題，
但不能僅憑本次實驗斷言直接 bytes 方案不可行，也不能將原因完全歸咎於訓練輪數。
先單獨驗證「bytes → 低解析度 RAW」在獨立影片上的能力，再增加生成細節或複雜時間融合，比盲目加深後端更有依據。

視覺結果仍可見輪廓損失、平滑與區塊條帶；未進行影片時間一致性、新影片或目標設備串流延遲驗收。
目前最佳模型指 `runs/single-v1-refined/best.pt`，只代表本次模型候選中 RAW MAE 最低，不代表可部署。
