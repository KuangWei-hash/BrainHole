## 0. 一句話

`可以參考的方法.md` 明確列出「**從低解析度資訊產生 640 × 16 RAW 的重建網路**」是必須另外設計、尚未解決的部分。v10 就是補上這一塊：把卷積主體從高解析度網格搬到**低解析度網格**（每區塊少算 16 倍），用**相位感知的學習式 ×4 上採樣**取代固定 bilinear，預期在 Q=4 下首次真正贏過 bilinear／FSR 1 對照組，同時把每區塊 MACs 壓在 v7 的 1/16 以內。

## 1. 為什麼現在做 v10

### 1.1 現況：Q=4 下模型還沒贏過對照組

這是整份設計的起點。既有紀錄的實際數字：

| 方法 | 參數 | 資料 | 驗證窗口 | MAE | PSNR (dB) | 判定 |
| --- | ---: | --- | ---: | ---: | ---: | --- |
| Q=4 bilinear（輔助基準） | 0 | BBB Q=4 | 5,370 | **14.497267** | 20.471392 | 基準 |
| Q=4 v7（T=2，encoded＋decoded） | 114,828 | BBB Q=4 | 5,370 | 14.504695 | **20.471827** | **輸 0.007 MAE，數值初篩未過** |
| Q=5 bilinear（輔助基準） | 0 | BBB Q=5 | 5,370 | 17.552326 | 19.701981 | 基準 |
| Q=5 v7（T=2，encoded＋decoded） | 114,828 | BBB Q=5 | 5,370 | **15.121942** | 20.787027 | 過（MAE −13.85%） |
| Q=5 v9 plain16（單幀 decoded＋phase） | 1,172 | BBB Q=5 | 5,400 | 16.626771 | 20.079337 | 過（MAE −5.12%） |
| Q=5 FSR 1 EASU 2x＋2x＋RCAS 0（主要基準） | – | BBB Q=5 | 5,400 | 17.205235 | 19.849065 | v9 領先 |

兩個關鍵事實：

1. **Q 越低，bilinear 越強。** Q=4 的 bilinear 是 14.497 MAE，Q=5 是 17.552。原因是 Q=4 的 decoded 幾乎就是原始低解析度值（實測 decoded 與原始低解析度的 MAE 只有 4.78），bilinear 因此拿到很好的起點；Q=5 的 decoded 誤差大，bilinear 被拉低，模型才顯出相對優勢。**現在正式設定是 Q=4，所以基準更難。**
2. **在 Q=4 上，v7 以 114,828 參數仍然輸給 0 個參數的 bilinear。** 這表示「把模型做大」不是解法，架構才是。

### 1.2 目標

- **必要條件**：在 Q=4 上，明顯優於同集合的 bilinear 與 FSR 1 對照組（[驗收標準.md](../驗收標準.md) 的核心條件）。
- **充分條件**：在**不同來源影片**（Tears of Steel）上仍成立。
- **附帶條件**：每區塊 MACs 與延遲符合 1.11 ms 預算（900 區塊/秒）。
- **非目標**：「精準還原」。依 `作法.MD`，結果與原始畫面大致相似即可，允許生成缺少的細節。因此 L1 最優解的「條件中位數」並非終點，視覺品質是並列目標。

## 2. 問題的精確定義

把幾何寫清楚，後面的設計每一項才有依據。

### 2.1 座標與張量

| 項目 | 值 | 說明 |
| --- | --- | --- |
| 目標 | 640 × 16 RAW8 Bayer 馬賽克 | 10,240 像素，一幀 30 條 |
| 輸入（畫面） | 160 × 4 RAW8 Bayer 馬賽克（decoded） | 640 像素 |
| 已知比例 | **1/16** | 每 8×8 tile 只有 1 組 RGGB quad 被取樣 |
| CFA 打包 | 4 個平面（R / G1 / G2 / B） | 每平面低解析度 **2×80**、高解析度 **8×320** |
| 縮放比 | **4×**（水平、垂直皆是） | 以「CFA 平面」座標計 |
| 相位 | 16 種 | 取樣在 8×8 tile 內的偏移 |

低解析度馬賽克與高解析度馬賽克的對應關係（由 `training-data-preparation/internal/dataset/image.go` 的 `Downsample` 推導）：

```
low[2j+dy, 2i+dx] = high[8j+py_raw+dy, 8i+px_raw+dx]        px_raw, py_raw ∈ {0,2,4,6}
```

改成以 CFA 平面座標表示（每個低解析度 quad 是一組 RGGB）：

```
plane_low[j, i]  =  plane_high[4j + py, 4i + px]           px = p%4, py = p//4 ∈ {0..3}²
```

**這條式子是 v10 的關鍵。** 它表示：

- 低解析度樣本 (i, j) 在高解析度平面裡固定落在 4×4 單元格中的第 (px, py) 格；
- 四個 CFA 平面的偏移**完全相同**，不需要分別處理；
- 相位只影響一個整數子像素位移。

### 2.2 資訊量分析：這題有多難

- 目標 10,240 像素中只有 640 個是已知的（JPEG XS 解碼後的值），其餘 **9,600 像素必須靠先驗補出**。
- 垂直方向特別惡劣：16 個高解析度列中只有 4 列被取樣，而且相隔 8 列。bilinear 在垂直方向其實是在相隔 8 列之間做線性內插。
- 因此**水平的紋理延續性是唯一能補出垂直細節的線索** → 模型必須有足夠的水平感受野。
- 已知像素上的輸入不是完美的：Q=4 的 decoded 與原始低解析度 MAE 為 4.78（BBB）／5.00（ToS），所以模型在已知位置還有去雜訊的空間。

### 2.3 這是什麼文獻問題

把高解析度 Bayer 馬賽克視為輸出，就是**在 CFA 上做超解析度**；因為四個 CFA 平面彼此有 1 像素的相對位移、必須聯合處理，所以更精確地說是 **CFA 的聯合去馬賽克＋超解析度（joint demosaicing + SR）**，再加上 JPEG XS 造成的失真 → 屬於**壓碼還原＋超解析度**的交叉領域。

`可以參考的方法.md` 已經把這個問題定位成「從低解析度資訊產生 640 × 16 RAW 的重建網路」，並指出 EMVD（RAW 影片去噪、遞迴式歷史融合）只提供前端思路、不能直接用。v10 補的是後半段。

## 3. 核心診斷：v9 為什麼幾乎贏不了

### 3.1 感受野不對

v9 plain16 的結構是：先把 decoded 用相位對齊 bilinear 放大到高解析度平面網格（8×320），再做 `Conv3×3 4→16 → Conv3×3 16→4`。

在 8×320 的網格上，一層 3×3 卷積只覆蓋 **±1 個高解析度平面像素**，也就是輸出馬賽克的 ±1 像素。兩層的理論感受野是 ±2 像素。

對照 4× 超解析度需要什麼：要把一個低解析度樣本推廣到 4×4 的高解析度單元格，並且要判斷邊界、紋理方向、跨色相關性，**合理感受野至少要 ±10…30 個輸出像素**。v9 的 ±2 像素在數學上不可能學到東西，這就是它只能把 bilinear 微調 5% 的原因。

v7 用 12 層 3×3 堆到 ±11 像素，確實贏了 Q=5 的 bilinear 13.85%，但**仍然輸給 Q=4 的 bilinear**，而且每區塊要 279M MACs。

### 3.2 算力花錯地方

v7 的所有卷積都發生在 8×320 = 2,560 個位置的高解析度網格上。若改成在低解析度的 2×80 = 160 個位置上做，同一層卷積：

- 位置數少 **16 倍**（2,560 → 160）；
- 每層的感受野換算到輸出馬賽克多 **4 倍**（1 低解析度像素 = 4 高解析度像素）。

也就是說「搬到低解析度」同時得到 **1/16 的算力** 和 **4 倍的感受野**。這是 v10 的主要杠杆。

### 3.3 現況對照表（每區塊 640×16）

| | 卷積所在網格 | 感受野（輸出馬賽克像素） | 參數 | MACs/區塊 |
| --- | --- | ---: | ---: | ---: |
| v9 plain16 | 高解析度 8×320 | ±2 | 1,172 | 2.95 M |
| v7（5 殘差區塊） | 高解析度 8×320 | ±11 | 114,828 | 279.2 M |
| **v10 C=32 N=8** | **低解析度 2×80** | **±34** | 95,812 | **17.9 M** |

v10 的感受野是 v7 的 3 倍，MACs 是 v7 的 1/15.6，參數還比 v7 少 17%。

## 4. v10 架構

### 4.1 對齊正式規格

v10 **不違反** `作法.MD` 的輸入契約。契約是：

| 順序 | 對應時間 | 每份內容 | 大小 |
| --- | --- | --- | ---: |
| 0 | 當前幀 t、本條 b | 長度欄位 + JPEG XS 編碼資料 + 尾端補零 | 640 bytes |
| 1 | 前 1 幀 t−1、本條 b | 同上 | 640 bytes |

decoded 分支每份 160 × 4 RAW8 RGGB、640 bytes，共 1,280 bytes；時間權重 w₀ = 0.5498（當前）、w₁ = 0.4502（前一）。

v10 的架構因此是：

```
encoded [B,2,640] ── Byte Encoder（共用）──► 每幀特徵 e_t, e_{t-1}
decoded [B,2,4,160] ── 打包成 4 個 CFA 平面 ──► 每幀平面 [B,2,4,2,80]
phase [B,2] ──► 相位嵌入（＋相位感知上採樣位移）
                     ▼
        每幀特徵在低解析度網格（2×80）上融合（w₀ / w₁）
                     ▼
        Stem → N × NAFBlock(C) → 上採樣 → 重建殘差 → 640×16 RGGB
```

`encoded` 分支與 `T=2` 皆保留為**預設**，但都做成可關閉的開關，讓 §8 的消融能把「encoded 有沒有幫上忙」「時間有沒有幫上忙」講清楚。理由見 §4.2(f)。

### 4.2 資料流（畫面主幹）

```
decoded  [B,4,160,4]  (RGGB 馬賽克)
   │  pixel_unshuffle(2) → 每個 CFA 平面 2×80
   ▼
[ B, 4, 2, 80 ]                     低解析度 CFA 平面
   │  concat 相位嵌入（P 個通道，broadcast）
   ▼
Stem  Conv3×3(4+P → C)              @ 2×80
   ▼
Body N × NAFBlock(C)                @ 2×80     ← 所有算力花在這裡
   ▼
Up    Conv3×3(C→C)                  @ 2×80
      1×1(C→16C)                    @ 2×80
      相位子像素循環位移 (px, py)
      PixelShuffle(4)               → 8×320
   ▼
Tail  Conv3×3(C→4)                  @ 8×320    ← 殘差在高解析度上產生
   ▼
  +  當前幀相位對齊 bilinear 基線      @ 8×320
   ▼
PixelShuffle(2) → [B,1,16,640]      高解析度 RGGB 馬賽克
```

時間融合的位置：**在低解析度網格上、Stem 之後、Body 之前**。理由是時間融合是逐位置的加權平均，位置越早做，參數越省；而且兩幀的內容對齊只差 phase，沒有運動補償，低解析度上做融合的誤差與高解析度上做是一樣的（都是未對齊的加權平均）。

### 4.3 逐項設計與理由

**(a) 主體放在低解析度網格** — §3.2 的 16 倍算力與 4 倍感受野。文獻支持：NAFNet 附錄的 "Downsample/Upsample Layer" 就是「1×1 先把通道加倍，再接 pixel shuffle」；NTIRE 2025 RawRTSR 的冠軍 ECAN 也是「淺層特徵 → 深層 → PixelShuffle → 重建殘差加在 bilinear 上」；`可以參考的方法.md` 建議的重建頭也是「小型 2D CNN 搭配上採樣，輸出四個 Bayer 色彩平面，再依 RGGB 排列還原」。

**(b) NAFBlock 作為區塊本體** — SimpleGate（把通道切兩半相乘）＋ Simplified Channel Attention ＋ LayerNorm，**完全沒有 ReLU/GELU/Sigmoid**。理由有二：
   - 沒有非線性啟動函式 → int8 量化與嵌入式推論更友善（這條專案一路從 v9 的「無 ReLU」往下走）；
   - NAFNet 的 ablation 顯示 LayerNorm 對訓練穩定度很重要（小 batch 時尤其）。
   - 代價是每個 block 參數較多（見 §6 的成本表）。
   - EMVD 的輕量 CNN（兩層 3×3、16 通道、ReLU）是另一種選擇；v10 用 NAFBlock 是為了拿回感受野，而不是省參數。

**(c) 相位感知的學習式上採樣（v10 的專利技術點）**

   固定 pixel shuffle 的對齊是錯的。由 §2.1 的式子 `plane_low[j,i] = plane_high[4j+py, 4i+px]`，若網路學到的是「相位 0 對齊」的重建函數 K[a,b,u,v]（用 LR[i+u,j+v] 預測 HR[4i+a, 4j+b]），那麼相位 p 下正確的重建就是：

   ```
   out_p[a, b] = out_0[(a - px) mod 4, (b - py) mod 4]
   ```

   也就是說**只要把輸出的 16 個子像素通道做一次 (px, py) 的循環位移**，同一套權重就對所有 16 個相位都正確。這個操作：
   - 零參數、零 MACs（只是 channel roll）；
   - 是**精確**的，不是近似；
   - 讓「學習式上採樣」取代固定 bilinear 成為可能——因為固定 bilinear 無法用同一套權重處理 16 種相位，學習式上採樣卻可以。

   實作上：把上採樣前的通道 reshape 成 `[B, C, 4, 4, H, W]`，沿 (2, 3) 軸以 `(py, px)` 做 `torch.roll`，再 `PixelShuffle(4)`。

   **這是 v10 與既有 v7／v9 最大的結構差異**：v9 的相位只影響 bilinear 的取樣網格，CNN 完全不知道相位是什麼；v10 的相位會直接改變上採樣的對齊。

**(d) 相位嵌入** — 16 相的相位以一個可學習的 embedding 展開成 P 個通道，concatenate 到 stem 輸入。文獻依據是 Samsung Labs 的統一去馬賽克工作：**把 mosaic 版面資訊編碼進輸入、訓練單一模型**，其表現優於「每種版面各訓一個模型」。對我們而言，16 相就是我們的「版面」。`可以參考的方法.md` 也已建議加入 phase_id（v9 已實作在輸出端，v10 改在 stem 輸入端，讓整個主體都知道相位）。

**(e) 殘差基線** — 最終輸出是「當前幀相位對齊 bilinear ＋ 網路殘差」。這沿用 v7 的「當前本條 decoded 放大結果為直接輸出路徑，CNN 預測本條殘差」的做法，也是文獻中被反覆驗證的（NTIRE 2025 RawRTSR、Scale-Symmetric、CISR 都是把重建當成 bilinear 之上的殘差），好處是網路只需要學高頻修正，初期訓練穩定。

**(f) encoded 分支與時間幀數：保留為可消融的開關，而不是直接刪掉**

   `作法.MD` 的正式輸入契約包含 encoded（2 × 640 bytes）與 T=2。v10 預設都保留，但把「關掉」做成開關，理由如下：
   - **資訊理論上的假設**：decoded 是 encoded 的確定性函數（同一份碼流解出同一張圖），所以 decoded 已經包含 encoded 的全部資訊，encoded 分支的**邊際資訊增益應為零**，只會增加參數與延遲。
   - **但既有證據無法分辨**：v7 與 v9 同時差了 encoded、幀數（2 vs 1）、深度（12 層 vs 2 層）三件事，v7 的 13.85% 優勢很可能來自感受野而不是 encoded。**v10 必須用固定主體的消融把這件事講清楚**，否則永遠只會停在「不知道哪個有效」。
   - **頻寬不是理由**：encoded 位元組本來就在傳輸線路上，用不用都不影響頻寬；純粹是算力與複雜度的取捨。
   - 時間幀數同理：`作法.MD` 已把 T 由 16 改成 2，且 `可以參考的方法.md` 提醒「物體移動時歷史內容可能移出同一個 640×16 區塊，單靠時間加權無法保證對齊」，有殘影風險。

**(g) 單幀與雙幀都要能跑** — v10 的 `--history 1` / `--history 2` 都要支援，且兩者共用同一套權重結構（時間融合退化為恆等）。這樣 §8 的消融不需要改架構。

### 4.4 為什麼不做的事（以及為什麼）

| 不做 | 理由 |
| --- | --- |
| U-Net / 多尺度 | 低解析度平面只有 2 列高，垂直方向的池化會立刻失去意義；多尺度在這個幾何上沒有空間 |
| Transformer | 感受野要靠 token 化，參數與延遲都遠超目前預算；NAFNet 的 ablation 顯示簡單 block 已經足夠 |
| GAN / 感知損失（現在） | `可以參考的方法.md` 的順序是「重建有效後再實驗生成式 loss」。v10 先把重建本體做對，生成式訓練留待 v10 之後（可參考 TecoGAN） |
| 預先上採樣（bilinear 先放大再卷積） | v9 就是這樣，導致感受野太小；這是 v10 要改掉的 |
| decoded 一致性損失（強制輸出在已知位置等於 decoded） | 方向錯了：decoded 是有損的（MAE 4.78），強制一致會把模型拉回有損值。已知位置應該由 L1 損失去學「去雜訊後的真值」，不是學 decoded |
| 運動補償 / 時序對齊 | `作法.MD` 列為「待驗證」；v10 先做架構，不疊加這個不確定度 |

## 5. 訓練設計

### 5.1 資料切分

沿用已在 Q=4 資料上確立的切分，不重新發明：

| split | 資料庫 | 內容 | 用途 |

| validation | `tears-of-steel-q4-shared-v4-raw8.sqlite` | 22,024 幀、660,720 筆 | **未見來源影片**泛化驗證 |

兩庫共用標頭 ID 相同（`834b4d34…`），`train.py --val-db` 可直接使用。

**保留集（報告用）**：沿用既有慣例取 frame 720…899 共 5,400 筆，讓 Q=4 的新結果可以與 v7 Q=4 的 5,370 窗口、v9 的 5,400 窗口並列；**但要明確標註視窗數不同、不可直接當成同集合比較**。

**過擬合風險**：train 只有 27,000 筆、來自單一部影片，這是 v10 最大的風險。對策見 §5.3。

### 5.2 輸入與目標

- 輸入：`decoded` 欄位（160×4 RAW8）、`jpegxs_payload`（encoded）、`phase_id`。
- 目標：`raw_bayer_target`（640×16 RAW8）。
- decoded 由原生 Go 解碼器產生，與上游 Rust 解碼器逐 byte 相同（已驗證），符合 `作法.MD`「必須由同一份 encoded 實際解碼，不能用高解析度標籤降採樣替代」的要求。

### 5.3 增強

Bayer 資料的增強有陷阱：直接把打包的 4 通道 RAW 翻轉會產生**物理上不可能的馬賽克**（BayerAug 論文的核心發現）。所以分成兩類：

**(a) 光度增強（安全，必做）** — 對 decoded 與 target 施加**同一個**變換：
   - 隨機曝光增益 g ∈ [0.7, 1.4]、隨機偏移 o ∈ [−16, 16]、隨機 gamma ∈ [0.8, 1.25]。
   - 這是 RAW 的物理合理變化（照度與白平衡），不破壞任何版面結構。
   - 幅度依據：train 資料的 decoded 與原版低解析度 MAE 為 4.78，所以增強的擾動量級要明顯小於資料本身的變異，否則會教模型去適應不屬於 codec 的誤差。

**(b) Bayer 安全幾何增強（要做，但需要版面編碼擴充）**
   - 水平翻轉：可精確推導（見下），會同時把相位 (px, py) 變成 (6−px, py) 並交換 quad 內的 x 次序（R↔G1、G2↔B）。
   - 垂直翻轉：(px, py) → (px, 6−py)，同樣交換 quad 內的 y 次序（G1↔G2）。
   - 問題：翻轉後**馬賽克版面從 RGGB 變成 GBRG 等**，這在真實感測器上不成立，但對本專案（資料由 RGB 通道直接合成）是合法的額外資料分布。
   - 解法：把相位從 16 種擴充成 **32 種（16 相位 × 2 種翻轉奇偶）**，並把翻轉奇偶也編碼進網路輸入。於是網路學到的是「版面無關」的重建函數。這也正好呼應 mosaic-embedding 文獻。
   - **排程**：v10-A（主體）先用 (a) 訓練；(b) 做成獨立對照項，避免一開始就引入不確定的複雜度。

**(c) 排除的增強**：直接翻轉打包 4 通道 RAW（BayerAug 已證明錯誤）、跨 8×8 tile 邊界的隨機裁切（會破壞相位）、時間反轉（內容不對稱）。

### 5.4 損失

主損失用 **Charbonnier（ε = 1e-3）** 在高解析度 RAW 上：比 L1 對離群值穩健、對邊界比 L2 銳利，是 SR 領域的標準；`可以參考的方法.md` 也已指定「初期可用 RAW L1 或 Charbonnier loss 穩定訓練」。

可選加項（各自做消融）：
- **小波子頻帶損失**：依 `可以參考的方法.md` 的建議，**必須先拆成四個 RGGB 平面再比較**，不可直接套在 Bayer 馬賽克上（會混合顏色排列與真實紋理）。額外的好處是：JPEG XS 本身就用 5/3 小波（levels=1/0），所以小波域損失與編碼器自己的頻帶結構對齊。
- **頻域損失**：FFT 的實部／虛部 L1，鼓勵高頻恢復（NTIRE 2025 RawRTSR 冠軍用 Charbonnier＋Frequency）。
- **邊緣損失**：Sobel 梯度 L1，強化邊界銳利度。

不使用：感知／VGG 損失（會製造假細節、且需要可微分的顯色流程）、一致性損失（見 §4.4）。

### 5.5 最佳化

- AdamW，lr 1e-3（主體在低解析度，梯度尺度與 v9 不同，需要重調），cosine 退火，warmup 200 步。
- weight decay 1e-4（資料量小，需要正則）。
- 梯度裁剪 1.0。
- 早停：以 **未見影片 validation（ToS）** 的 MAE 為準，而不是 train 的 loss。這一點很重要——v7 在 Q=4 就是在同影片保留集上輸給 bilinear，若只看 train loss 會誤判。
- 批次：每個樣本只有 640×16 個目標像素，batch size 可開大（64–256）。

## 6. 參數量、算力與延遲預算

由 `估算成本.py` 產生（解析式估算，不含 bias／LayerNorm／逐元素操作）：

| 模型 | 卷積網格 | 感受野（輸出馬賽克像素） | 參數 | MACs/區塊 | @900 區塊/秒 |
| --- | --- | ---: | ---: | ---: | ---: |
| v9 plain16（現況） | 高解析度 8×320 | ±2 | 1,172 | 2.95 M | 2.65 GMAC/s |
| v7（5 殘差區塊） | 高解析度 8×320 | ±11 | 114,828 | 279.2 M | 251.3 GMAC/s |
| v10 C=16 N=4 | 低解析度 2×80 | ±18 | 18,084 | 4.20 M | 3.78 GMAC/s |
| **v10 C=16 N=8** | 低解析度 2×80 | **±34** | 27,172 | **5.62 M** | **5.06 GMAC/s** |
| v10 C=24 N=8 | 低解析度 2×80 | ±34 | 56,308 | 10.92 M | 9.83 GMAC/s |
| **v10 C=32 N=8** | 低解析度 2×80 | **±34** | 95,812 | **17.88 M** | **16.09 GMAC/s** |
| v10 C=32 N=12 | 低解析度 2×80 | ±50 | 128,324 | 23.02 M | 20.72 GMAC/s |
| v10 C=48 N=12 | 低解析度 2×80 | ±50 | 276,196 | 47.92 M | 43.13 GMAC/s |

（感受野欄為「每側」像素數。）

**建議的第一組設定**：`C=32, N=8`（≈96K 參數、17.9M MACs），因為：
- 感受野 ±34 像素已遠超過 4× 超分所需；
- MACs 是 v7 的 1/15.6；
- 延遲預算：900 區塊/秒 = 每區塊 **1.11 ms**（`可以參考的方法.md`）。17.9M MACs 在 1.11 ms 內需要約 **16.1 GMAC/s**，對現代 NPU／DSP 的 int8 路徑是可行的量級；v7 的 251 GMAC/s 則明顯超標。

若後續要做 int8 量化或蒸餾，`C=16 N=8`（27K 參數、5.6M MACs，需 5.1 GMAC/s）是備援。

> 這些是**靜態成本估算**。實際延遲必須在目標裝置上量測（見 §7.4），因為記憶體搬運與 kernel 效率在嵌入式上常比 MAC 數重要。1.11 ms 是整體預算，還要分給 JPEG XS 解碼、資料傳輸與其他環節。

## 7. 評估與驗收

### 7.1 對照組（缺一不可）

| 對照 | 說明 | 為什麼要 |
| --- | --- | --- |
| **FSR 1 EASU 2x＋2x＋RCAS 0** | 目前的主要基準（`作法.MD`） | 官方實作，非本專案自製 |
| FSR 1 EASU 2x＋2x | 不加銳化 | 區分「上採樣」與「銳化」的貢獻 |
| RAW bilinear（輔助定位） | 相位對齊 bilinear | 最低基準，也是 Q=4 的真正難關 |
| nearest | 下限 | |
| JPEG XS 解碼 + 固定去馬賽克 | 上游解碼器路徑 | 確認模型不是只在學解碼器誤差 |

### 7.2 集合與必報指標

- **主集合**：Tears of Steel（未見來源影片）抽樣的固定視窗（數量要固定並寫在報告裡）。
- **次集合**：BBB frame 720…899 的 5,400 條保留集（與歷史並列）。
- 每個集合都必須同時報：MAE、PSNR、**逐區塊勝率**（模型比對照組好的比例）、**最差 10% 區塊的 MAE**。
- **必報負面結果**：若模型在某些區塊明顯更差，要列出該區塊的特徵（不能只報平均）。

### 7.3 視覺驗收

- 固定相鄰影片片段、逐區塊並排圖：目標／bilinear／FSR 1／模型。
- 用同一套固定去馬賽克轉 RGB 後比較，避免各自去馬賽克引入差異。
- 檢查項目：邊緣銳利度、是否出現假紋理或鬼影、已知像素位置是否被抹平、色邊是否產生。
- 因為「允許生成缺少的內容」，視覺是**並列**通過條件，不是只有數值。

### 7.4 效能門檻（品質階段之後）

- 目標裝置、batch = 1、單區塊到達即處理。
- 640×480@30 FPS = 每秒 900 區塊 = 每區塊 1.11 ms。
- 同時報：模型推論時間、JPEG XS 解碼時間、端到端時間。
- v10 的模型輸入（decoded）已經在介面上，**不需要額外頻寬**。

### 7.5 通過條件（v10 的驗收）

1. Q=4、BBB 保留集：MAE < 14.497267（bilinear）**且**優於 FSR 1 對照組。
2. Q=4、Tears of Steel（未見影片）：同樣勝過兩個對照組。
3. 逐區塊勝率 > 60%（不只是平均贏）。
4. 視覺驗收通過，沒有新增鬼影或假紋理。
5. 每區塊 MACs ≤ 20M（預算），實際延遲符合 1.11 ms。

**A 是關鍵實驗**，且 A 與 B 的對比是整份設計的生死判據：

- E 與 F 是把「encoded 與時間到底有沒有用」講清楚的實驗；這兩項的結論會決定正式部署時的輸入契約要不要瘦身。

## 9. 風險與限制

| 風險 | 影響 | 緩解 |
| --- | --- | --- |
| 訓練資料只有 27,000 筆、單一影片 | 過擬結、未見影片泛化差 | 光度增強；把 ToS 當未見集合量測；必要時考慮「train = BBB + ToS 前段／val = ToS 後段」的場景切分，但必須明確記錄切分方式 |
| 題目本身是病態的（16 像素只有 1 個已知） | MAE 天花板可能就在 14 附近 | 若 A 接近天花板，改以 PSNR／高頻指標與視覺品質為主目標，並記錄天花板分析 |
| 相位子像素位移的實作正確性 | 錯了會讓模型學到不一致的對齊 | 寫單元測試：對每個相位 p，驗證「相位 p 的 LR 樣本落在 HR 的 (4i+px, 4j+py)」；並驗證位移操作在 p 與 p' 之間的關係 |
| 垂直方向先天不足 | 12/16 列幾乎全靠補出 | 在報告中量化「水平方向誤差 vs 垂直方向誤差」，讓瓶頸可見 |
| T=2 的時間對齊無運動補償 | 鬼影 | 視覺驗收專項檢查；若 A（F）顯示 T=2 沒有改善且有鬼影，正式契約應考慮收斂到 T=1 |
| 缺第三部影片 | 沒有獨立 test split | 明確標示 test split 尚不存在 |
| FSR 1 對照需要 RGB 轉換 | 對照公平性 | 沿用既有 FSR 1 評估的輸入轉換規範（位置 (4u+1.5, 4v+1.5)、兩綠平面平均），不重新發明 |
| EMAVD 式可學習小波變換 | 可能與 JPEG XS 的 5/3 結構更契合 | 屬於後續選項（v10-A/B 的中間實驗），不塞進第一版 |
