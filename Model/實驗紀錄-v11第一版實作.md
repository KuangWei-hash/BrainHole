# 實驗紀錄：v11 第一版實作與流程檢查（相位感知多幀融合）

日期：2026-11-22
類型：實作 + 流程檢查（flow check，非完整訓練、非品質驗收）
前置：[v11 時序量測](./實驗紀錄-v11時序量測.md)、[v11 設計文件](./v11/README.md)

## 1. 目的

使用者同意「v11 可以嘗試看看」。本回合的目標是把 v11 從設計推進到**可訓練的程式碼**，
並用真實資料證明流程能跑通、模型能學、且多幀輸入確實被使用。**不含品質驗收**。

## 2. 實作內容

| 檔案 | 內容 |
| --- | --- |
| `Model/v11/phase.py` | 相位精確重組：把每幀 decoded 依其 phase 放到 640×16 網格的精確位置，輸出量測值與覆蓋遮罩。零參數、零插值。 |
| `Model/v11/model.py` | `FusionNet`：相位感知的低解析特徵對齊（已知 lattice 位移 + 學習到的連續次像素運動）、逐像素學習式融合權重、量測分支與覆蓋率通道、重建頭。 |
| `Model/v11/data.py` | 從 Q=4 v4 資料庫直接取 T 幀視窗（decoded／phase／target），視窗不跨切分。 |
| `Model/train_v11.py` | 訓練入口（L1 on normalized RAW），走 `run_logged` 紀錄。 |
| `Model/test_v11.py` | 18 項單元測試。 |

### 相位重組的驗證（`test_v11.py`）

- 由 phase 反推的取樣位置與 `decoded` **逐值相等**（並與 Go `Downsample` 的互逆對照）。
- **16 個相位恰好鋪滿 640×16 馬賽克，每個像素被量測恰好一次**（聯集覆蓋 10,240/10,240，
  逐像素量測次數唯一值為 1）。
- 單幀覆蓋率恆為 **1/16**；T 個互異相位的聯集為 **T/16**。

### 對齊的物理量

由量測得知移動像素的位移多在 ±2 高解析像素內（`dx=0` 佔 49.9%、`|dy|≤2` 佔 63.8%），
且**相機幾乎不動**（|dx| 中位 0.021 px、|dy| 中位 0.292 px）→ 動的是物件。
因此：

- 已知部分：相鄰幀的 phase 差 → lattice 位移（精確、整數、可直接套用）。
- 學習部分：物體的**次像素**運動 → `OffsetNet` 以 `tanh` 輸出連續偏移，上限 1 個低解析平面步（= 4 個高解析像素）。
- 對齊一律在 **CFA 平面內**進行，跨色不插值。

## 4. 失敗與修正紀錄（保留）

1. **`record_experiment.refresh_index` 對 metrics 不完整的紀錄會拋 KeyError**
   （`psnr_raw` 缺漏時）。已改成容錯（缺 PSNR 就只顯示 MAE）。
   第一次流程檢查因此中斷，該次紀錄與產物保留在 `Model/runs/v11-fusion-q4-flowcheck`。
2. **v11 測試初期失敗 5 項**，逐項修正：
   - `mask[b, frame, 0][rows, cols] = True` 是 advanced indexing，指派寫進暫存副本 → 改用 flat index。
   - `coverage()` 少縮一維 → 改為 `mean(dim=(2,3,4))`。
   - 測試斷言本身寫錯（`mask.all()` 應為聯集覆蓋；`coverage` 是逐幀比例）→ 修正斷言。
3. **`warp` 網格多一維**（`[B,1,H,W,2]`）→ 修正為 `[B,H,W,2]`；並確認
   `grid_sample` 的語意是 `output(x) = input(x + dx)`，故正偏移會讓內容左移，
   相位位移的符號據此確認（`phase_shift` 回傳 (off_ref − off_other)）。
4. **精確量測分支的偏移形狀與網格不符**（8×320 網格卻用 2×80 的偏移）→
   低解析偏移 ×4 換算到高解析平面網格，學習偏移以 nearest 上採樣 ×4 對齊。
5. **`exact_map` 的來源索引與目的索引用了不同索引空間**（LR 平面 160 vs HR 平面 2560）
   → 分別建立 source／destination 索引。
6. **motion-direction 量測第一版有 SSD 偏誤**：越界區域被當成 0 誤差，讓大位移假性變好，
   結果全部擠在搜尋邊界。改為只用完整重疊區域計分並除以有效樣本數後重跑，
   數字才合理（`runs-motion-direction.json`）。

## 5. 限制

1. 流程檢查僅 400 步、CPU、channels=16 的小模型，**不是完整訓練，不能當作品質結果**。
2. 與 v10／v9 的既有分數**不可直接混比**：不同的視窗集合、不同的模型規模、不同的訓練預算。
3. 目前只有 BBB Q=4 一部影片；T=1／T=4 的對照在同一影片內完成。
4. 尚未做影片視覺驗收、時序一致性檢查與延遲量測。
5. GPU 當時被 v10 監督批次佔用（stage C-v-prediction），故本次未啟動 GPU 訓練。
