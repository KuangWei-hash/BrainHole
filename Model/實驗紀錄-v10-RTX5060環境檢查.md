# v10 RTX 5060 環境檢查

本次確認單影片 Q=5 v10 實驗能在這台 Windows 電腦上執行。RTX 5060 有 8,151 MiB 顯存，系統有約 24 GB RAM。工作區 `Z:` 為 SMB 網路磁碟，原 `.venv` 在本機無法啟動。本次使用 `%LOCALAPPDATA%\BrainHole-v10-probe` 中的獨立 Python 3.13.9 環境和 PyTorch 2.7.1+cu128。CUDA 12.8 實測可用，PyTorch 支援本卡的 `sm_120`。

第一次啟動在 SQLite 開啟資料庫時失敗，錯誤為 `invalid uri authority`。第二次使用 Q=5 資料庫及 decoded 快取的本機副本，資料庫 SHA-256 與原實驗一致。模型照常從共享工作區執行，輸出也存回共享工作區。[網路磁碟失敗紀錄](experiments/records/training--v10-rtx5060-cuda-flowcheck--run-0ac75e320499.json)

短跑採雙路 decoded 與相位對齊 bilinear，輸出當前幀的 640×16 Bayer RAW。模型為 48 通道 FP32、v-prediction、有效 batch 16、microbatch 4、seed 42。沿用原切分，訓練幀 0–719、驗證幀 720–899，雙幀有效目標分別自幀 1 與幀 721 開始。短跑只在訓練集前 128 條估計殘差尺度，執行 128 次 optimizer update，共 2,048 條，耗時 9.58 秒。固定 256 條驗證使用 32 步 DDIM，耗時 2.44 秒。PyTorch 峰值顯存配置為 125.2 MiB，峰值保留為 158.0 MiB。此數值為 PyTorch allocator 統計。

唯一一輪保存了 `best.pt`、`last.pt` 和單條 RGB 預覽。該輪同 256 條的 `gamma=1` RAW MAE 為 22.17，bilinear 為 17.27。此結果僅驗證訓練、取樣和產物儲存流程，完整訓練與影片品質仍待驗證。本機 PATH 未找到 FFmpeg，完整影片輸出未執行。[短跑紀錄](experiments/records/training--v10-rtx5060-cuda-flowcheck-local-data--run-bd3362143773.json) · [設定](runs/v10-rtx5060-cuda-flowcheck-local-data/config.json) · [預覽](runs/v10-rtx5060-cuda-flowcheck-local-data/epoch-001-target-base-generated.png)

另以 v10 載入器重新讀取 `best.pt`，已確認權重可載回 CUDA 且保留 v-prediction 設定。

## 推論、影片與回歸測試

沿用上面的短跑權重、Q=5 本機資料與 32 步 DDIM。單條推論首次因 CPU 計算的 bilinear 在 GPU 上重新逐值核對而失敗。現在先在 CPU 核對輸入配對，再交由 GPU 推論。重跑 frame 721、block 10 成功，留下 10,240 bytes RAW 與 PNG，推論未讀取 target。[首次推論紀錄](experiments/records/evaluation--predict-v10-rtx5060-runtime--run-1a84deda4e8b.json) · [重跑推論紀錄](experiments/records/evaluation--predict-v10-rtx5060-runtime--run-8cc43e622d2d.json)

把 FFmpeg 9.0.2 放在 `%LOCALAPPDATA%\BrainHole-v10-probe\bin`，在執行評估的 PowerShell 程序加入 PATH。GPU 評估覆蓋 BBB frame 721–723，共 90 條。生成 MP4 和比較 MP4 均經 FFmpeg 完整解碼檢查。這次的 `gamma=1` RAW MAE 為 21.30，bilinear 為 16.35。兩者使用同 90 條與短跑權重，結果只用於檢查工具及產物。[評估紀錄](experiments/records/evaluation--eval-v10-rtx5060-runtime--run-115c15d8192a.json) · [比較影片](runs/eval-v10-rtx5060-runtime/comparison.mp4) · [生成影片](runs/eval-v10-rtx5060-runtime/generated.mp4)

共享磁碟上的全套回歸測試有 55 項通過。第 56 項嘗試由 UNC 路徑啟動官方 FSR 1 CLI 時遇到 Windows `WinError 5`。將該 CLI 複製到本機後，第一次重跑在 unittest 探索期間因測試模組路徑不一致而中止。改為在探索完成後切換測試的 CLI 路徑，實際跑完 EASU ×2 與 RCAS，全套 56 項通過。FFmpeg 與 FSR 使用本機執行檔，資料庫也沿用本機副本。[共享路徑測試](experiments/records/checks--checks-v10-rtx5060-runtime--run-288a6d9cc32e.json) · [測試探索失敗](experiments/records/checks--checks-v10-rtx5060-local-fsr--run-0406a4effe0c.json) · [56 項測試紀錄](runs/checks-v10-rtx5060-local-fsr-retry/tests.log)

### 在同一台電腦恢復環境

從 PowerShell 執行。FFmpeg 的 PATH 設定只套用到目前程序，每次開新 shell 需重新執行。

```powershell
Set-Location 'Z:\BrainHole'
$bh = Join-Path $env:LOCALAPPDATA 'BrainHole-v10-probe'
$py = Join-Path $bh '.venv\Scripts\python.exe'
$db = Join-Path $bh 'data\big-buck-bunny-30s-q5-shared-v4-raw8.sqlite'
$cache = Join-Path $bh 'data\decoded-q5-v4.npz'
$env:PATH = (Join-Path $bh 'bin') + [IO.Path]::PathSeparator + $env:PATH
& $py -B -c "import sys, torch, numpy, PIL; assert torch.cuda.is_available(); print(sys.version.split()[0], torch.__version__, torch.version.cuda, torch.cuda.get_device_name(), numpy.__version__, PIL.__version__)"
ffmpeg -version | Select-Object -First 1
Get-FileHash -LiteralPath $db, $cache -Algorithm SHA256
```

已驗證版本為 Python `3.13.9`、PyTorch `2.7.1+cu128`、CUDA `12.8`、NumPy `2.5.4`、Pillow `12.3.0`、uv `0.13.9`、`imageio-ffmpeg 0.8.1` 所附的 FFmpeg `9.0.2`。FSR 1 CLI 本機副本在 `$bh\fsr-check\tools\fsr1\v1.0.3\FidelityFX_CLI.exe`，只在需要 FSR 基準或跑該項測試時使用。

| `$db` | `training-data-preparation/拆好的訓練資料/big-buck-bunny-30s-q5-shared-v4-raw8.sqlite` | `11C05BDD430BA67FA84A986288C9E48786B92ADED73FA38C51661ACAAC8975EB` |
| `$cache` | `Model/runs/decoded-q5-v4.npz` | `1BFEE926A2D6428A5ACBFB89643E26D161C44B1F2E952481A3C1F49AA17F31AE` |

`Z:` 指向 SMB。SQLite 資料庫與解碼快取缺失時，從上表的共享來源複製到 `$bh\data` 後核對雜湊。訓練和評估從共享工作區執行並把輸出存回 `Model/runs`。若需要重建本機套件，使用 `$bh\uv.exe` 建立受 uv 管理的 Python 3.13.9 venv，PyTorch 從 `https://download.pytorch.org/whl/cu128` 安裝上列版本。用 `imageio_ffmpeg.get_ffmpeg_exe()` 找到隨套件安裝的執行檔，複製為 `$bh\bin\ffmpeg.exe`。

### 正式實驗授權後的指令

這是依已驗證配置整理的首組完整訓練指令。省略短跑的 `--max-steps` 和 `--scale-steps`，讓訓練使用完整資料和正式殘差尺度。每次用新輸出資料夾，從 `metrics.jsonl`、`best.pt` 及 `last.pt` 確認進度。CLI 目前從頭訓練，沒有 `--resume` 參數。

```powershell
$run = 'Model/runs/v10-q5-v-prediction-' + (Get-Date -Format 'yyyyMMdd-HHmmss')
& $py -B Model/train_v10.py --db $db --decoded-cache $cache --out $run `
    --device cuda --mode diffusion --prediction-type v --condition both `
    --channels 48 --epochs 20 --batch-size 16 --microbatch 4 --lr 0.0001 `
    --sample-steps 32 --validation-count 256 --seed 42
```

訓練完成後可先看同片的前 30 個有效驗證幀。`--stop-frame` 為排除上限。上面的 20 輪與下面的 30 幀範圍都是待執行項目。

```powershell
$eval = "$run-eval-721-750"
& $py -B Model/evaluate_v10.py --db $db --decoded-cache $cache `
    --checkpoint (Join-Path $run 'best.pt') --out $eval `
    --device cuda --start-frame 720 --stop-frame 751 --preview-frame 721 --steps 32 --video
```
