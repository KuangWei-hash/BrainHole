# v14 固定監視器場景的 codebook

**2026-11-23，肉眼比對後：v14 分數最佳但紋理不如 v12（v12 靠真實像素時間累積，有精細度結構性優勢；v14 的 DCT 殘差壓縮天生有上限），改用 v15（[v15/README.md](../v15/README.md)）v12+v14 各半融合，分數略降但使用者判定是目前肉眼最舒服的版本。**

**2026-11-23，demo.mp4 目前數值最佳組合：compact codebook＋使用者設計的簡化歷史混合，RAW MAE 5.5386（真實訊號基準贏 53.5%、贏 v12 26.3%）。** 做法：width=40／RANK=160／k=8 的切塊＋DCT 壓縮碼本（已修正為用真實 `decoded` 訊號訓練與測試，而非先前誤用的乾淨 RAW 反推樣本）提供單幀估計；當前幀相位量測到的位置不混合，其餘位置與上一幀最終輸出做 30%／70% 遞迴混合（掃過 50/40/30/20/10% 五個比例，30% 最佳）。另外確認 encoded payload 當 key 只適合精確比對（key 體積省 71%、準確率不變），不適合近似相似度搜尋（像素描述子仍是正解）。[完整紀錄](../實驗紀錄-v14-demo影片驗證與壓縮碼本.md)。

**2026-11-23，首次改用真實錄影 demo.mp4（非 BBB）驗證。** v12 時間混合改善幅度達 41.1%（BBB 僅 7.7%）；整條 RAW 查表真實重用率僅 0.80%，單相 160×4 索引查表仍輸基準 55%，與 BBB 結論一致不可行；切塊＋DCT 殘差壓縮碼本把 RANK 從 8 拉到 160（滿）後，RAW MAE 改善 9.7%→49.8%，且高頻／精確命中率同步轉正，codebook 僅 40.31 MB（整條查表的 6.9%）。（此段數字後來發現用了理想化訊號，已於上方條目修正。）

2026-11-23，確立研究方向。最終應用是固定視角的監視器。單支鏡頭能看到的場景和變化範圍有限，v14 的模型只需處理目標鏡頭實際會遇到的畫面。研究重點是利用重複出現的場景特徵，幫助接收端用少量傳輸資料重建條帶。

## 第一階段建立 codebook

1. 收集目標監視器的大量錄影，讓資料涵蓋它實際會遇到的變化，例如光照改變或物體經過。
2. 把錄影逐幀切成 **640 × 16** 的水平條帶。以現有的 640 × 480 畫面規格計算，每幀有 30 條。
3. 讓模型從這些條帶學習反覆出現的特徵，形成代表該監視場景的 **codebook**。

碼本直接由原始 RAW 建立。完整 RAW 查詢與表項都是 **640 × 16 RAW8 RGGB** 條帶，一筆 10,240 bytes。

**第一階段的驗收定義：完美查表 = 有限窮舉 = 誤差 0。** 有限集合是已收錄的完整 RAW 條帶。對集合內每個查詢，窮舉同位置的全部表項，必須找到逐 byte 相同的條帶，原樣取回。驗收要求每條皆精確命中。

有損碼本階段允許多條相近的 RAW 共用一個原型。以 L1 最近鄰分組、逐像素中位數更新原型。每位置 8 筆用 8 bit 儲存時，壓縮表項為 1.46 MiB、RAW MAE 1.6234。用 6 bit 儲存並直接在量化網格續訓後為 0.94 MiB、RAW MAE 2.1373，於第一輪後收斂。零誤差碼本繼續作為對照，容量與畫質門檻待目視選定。[有損碼本初試與精度量測](../實驗紀錄-v14-有損RAW碼本.md)

## 待確認的設計

錄影來源與格式、碼本的特徵表示與容量、是否利用條帶在畫面中的位置，以及串流重建時如何使用碼本，均待決定。第一個待驗假設是碼本能否在同一支鏡頭、未參與訓練的錄影中，幫助重建可辨識的場景細節，同時保留當下出現的物體與變化。
