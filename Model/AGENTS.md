# 模型實驗紀錄要求

使用者要求所有實驗結果都記錄下來。此規則適用本目錄後續工作。

- 訓練、評估、推理、解碼、效能量測、短流程檢查、負面結果、失敗與中斷都要留存，不只保存最佳模型。
- 執行既有 CLI 時保持 `run_logged` 包裝；每輪訓練保持 `update_active_record`，保存當下曲線。
- 新實驗入口也要接入自動紀錄，或在執行前建立等價的持久紀錄。
- Git 僅保存程式碼、文件、必要設定與文字實驗摘要（2026-11-22 使用者更新）：`experiments/records` 的 JSON 設定／曲線／數值與狀態仍納入 Git；`experiments/details` 的完整逐區塊數值與 `experiments/source_snapshots` 的重複程式快照只存本機並加入忽略清單。所有紀錄仍照常產生與保存，不得因不進 Git 而刪除或停用。影像、影片、權重、資料庫與 binary 不上傳 GitHub。
- `runs/` 的權重、圖片、影片留在原位置，紀錄保存位置、大小與最終雜湊；不要覆寫舊實驗來節省空間。
- 自動紀錄包含原始 argv、起訖時間、環境、資料及權重指紋、程式快照；不得刪掉包裝來跳過失敗紀錄。
- 實驗完成後補寫可理解的 Markdown 解讀，包含目的、改動、輸入／輸出、資料來源與切分、訓練設定、最佳輪、結果、限制及產物連結。
- 每次比較必須注明驗證窗口範圍、樣本數與訓練預算；不同集合的分數不得直接混比。流程檢查不能冒充完整訓練。
- 只記錄觀測到的結果；資料缺失就標示未知，不能補造歷史時間、指令、錯誤或程式版本。
- `實驗總表.md` 自動產生；改紀錄後使用 `record_experiment.py` 更新。歷史補登使用 `--backfill`，不覆寫已存紀錄。
- 原始數值、負面／失敗紀錄不得因後來模型改良而改寫。修正解讀時保留來源與修正理由。
- 目前優先品質可行性，效能留待後續檢視；紀錄仍須區分數值初篩、視覺驗收、新影片泛化與即時效能。
- 影片輸出偏好（2026-11-22）：之後只輸出各方法單獨的成果影片，保留完整畫面與原輸出解析度；不再產生並排縮小的 `comparison.mp4`，因為畫面太小、不利檢視細節。多個方法、生成強度或 seed 需要展示時，分別輸出並在檔名或紀錄標明。既有影片保留，不回刪歷史產物。
- 視覺合格線（2026-11-22）：使用者將 v12 相位權重每幀遞減 0.02 的現有成果定為「堪用、最低合格線」。後續候選須保住其可見材質、輪廓與時序穩定；MAE 更低不等於通過人眼驗收。v13 的設計、預登錄計畫與執行狀態見 [v13/README.md](v13/README.md)。

## README 隨實驗同步更新（2026-11-22 使用者要求）

- 每次訓練、評估、目視比較或研究決策有新結論時，同一輪工作先保存實驗原始紀錄及 Markdown 解讀，再檢查並同步更新根目錄 `README.md` 和 `Model/README.md`。失敗、退步、中斷與使用者否定也要檢查，不只在產生更好分數時更新；若首頁結論未改變，可保留原摘要，在實驗紀錄說明原因，無須堆入每個流程檢查。
- 根目錄 README 開頭持續保留最終目標及探索階段的定位；「目前探索到哪裡」須反映最新有證據的結果、目前視覺基準、主要限制及下一個待驗假設，注明狀態日期並連結來源紀錄。更新現有摘要，歷史細節留在實驗文件及總表，不把新結果一段段堆在首頁最前面。
- `Model/README.md` 同步維護當前方法、可用入口及操作狀態；根目錄與模型文件不得對目前候選、品質基準、是否已實作／訓練有互相矛盾的說法。歷史版本的「目前」「執行中」只能保留在明確標示的歷史區段中。
- 數值初篩、使用者目視接受、新影片泛化與即時效能分別標示。較新的版本或較低 MAE 不自動取代既有視覺基準；候選升降級以實際證據及使用者判斷為準。設計與待執行項目不可寫成已完成成果，狀態日期不能冒充實驗執行日期。
- 完成實驗工作前，核對兩份 README 的結果、限制、日期及來源連結。這是隨工作觸發的文件維護要求，不代表自動啟動訓練、排程或推送 GitHub。
